SHEET 1

Zones and the one rule that makes this an architecture

Three trust zones. The rule they exist to express: no client, internal or external, holds a credential for a system of record. That rule is currently broken, and the diagram says so. The proxy/ tree that used to hold every signed trigger URL server-side has been removed, so both clients now call each Power Automate flow directly with a signed URL configured into them at deploy time. A signed trigger URL is the credential. The wall is therefore drawn around the flow endpoint, which is the only remaining place any control can be enforced.

Public — no authentication Internal — Entra ID (provisioned, inert until step 8) Systems of record — each flow enforces its own callers
SHEET 2

Layer dependencies — measured, not asserted

Edge labels are actual counts of cross-layer import specifiers — static, bare and dynamic — resolved to paths and bucketed by top directory. The static graph is acyclic: no layer statically imports from one above it, which is what lets a layer be built, tested and deleted independently.

There is exactly one upward reference and it is drawn rather than hidden: core/boot.js dynamically imports all 29 modules to register them with the router. That is a composition root, the standard place for the dependency rule to invert, and it is the reason this sheet distinguishes the two kinds of edge instead of claiming a clean hierarchy.

An earlier version of the generator matched only from '…' and so reported a tidier graph than the code actually has — it missed bare and dynamic imports entirely. The counts below are the corrected ones.

Workspace relationships — 9 destinations, 20 technical routes

Nine workspaces are primary navigation. The other twenty routes are real and routable but are reached through a workspace rather than from the sidebar — a deliberate choice recorded in workflow-clarity.config.js, so the navigation shows nine places to go rather than twenty-nine. Solid arrows are declared handoffs: the journeys the platform expects.

SHEET 4

Correspondence lifecycle — four channels, one record

The test of whether the correspondence model was right: four channels of arrival, and the model gains exactly one field value to distinguish them — channel. Nothing else changes. Lanes are who acts; the gateway is the one genuine decision point; everything right of the merge is common.
